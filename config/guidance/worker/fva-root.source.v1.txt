[R3] RUNTIME AND DEPENDENCY FACTS
- Production containers run Python 3.11 (agent images build from "python:3.11-slim").
  Validate compatibility against 3.11. A newer local interpreter will happily compile
  syntax that is a SyntaxError in production; local py_compile will not catch it.
- Each agent pins dependencies in two files: "requirements-prod.txt" is the
  human-edited statement of intent, and "requirements-prod.lock.txt" is GENERATED and
  fully resolved — the lock is what the image installs. Never hand-edit the lock. A
  change to "requirements-prod.txt" without a regenerated lock has no effect on the
  image.
- This checkout is on a native Linux path. WSL/UNC-specific workarounds described in
  the repository's documents do not apply here.

[R4] CROSS-CUTTING IMPLEMENTATION INVARIANTS
- ChromaDB knowledge bases: every agent's "knowledge_base.py" deletes before
  upserting inside initialize_kb() — collection.delete(where={"source": filename}) —
  to stop stale chunks accumulating when KB content is updated. Preserve this.
- n8n workflow definitions are NOT part of this repository's Python code. Post-call
  WhatsApp delivery faults are fixed in the n8n workflow, not in agent code. Do not
  "fix" them by changing Python.
- WhatsApp number normalisation for the Kavya handover path lives in
  "Kavya/handover.py::normalize_whatsapp" and sends BARE DIGITS (e.g. 94771234567)
  with no "@s.whatsapp.net" suffix — the n8n workflow owns JID formatting. The agent
  never blocks on that webhook failing; every error is swallowed and the guest is
  still promised a callback.
- Flico's Asterisk/SIP pilot under "asterisk-flico/" is ADDITIVE: it does not replace
  Twilio webhooks or ConversationRelay. Do not point Asterisk at "/voice/incoming" —
  that route returns TwiML for Twilio. Do not modify Kavya for that pilot.
  "ENABLE_ASTERISK_ARI" is false by default. Asterisk's public RTP range and Flico's
  external-media listener range are deliberately disjoint; do not overlap them.
- Kavya's availability data originates from a booking integration hosted outside this
  repository and reached over HTTPS. Treat it as an external dependency: never
  disable, administer or reconfigure it.
- Repository documents carry dated notes that later text contradicts (for example a
  June 2026 note warning that part of the admin knowledge-base feature may exist only
  in a different checkout). When a document and the code disagree, the code wins.
  Report the stale documentation; do not edit it unless it is in your allowed_paths
